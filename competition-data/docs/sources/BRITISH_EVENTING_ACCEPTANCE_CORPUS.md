## Coverage gaps

- The current working corpus is 2026-heavy because `/latest-results` lists current/latest result events.
- Historical links exist on event pages and must be used to add a second calendar year to the accepted corpus.
- Withdrawals, retirements, eliminations and corrections must be recorded from parsed real rows before production readiness.
- Persistence/API verification must be completed across the accepted corpus before changing status to `production_ready`.
